# Zox Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Commits:** Do not `git commit` unless Jayant explicitly asks. Commit steps below are checkpoints only.

**Goal:** Make Zox feel **finished** for daily use and trustworthy for `zox-code` npm installs—accurate docs, green quality gates, clearer first-run UX, and small CLI/TUI gaps closed—without starting new Phase 2 feature tracks.

**Architecture:** Polish is mostly **horizontal**: sync `spec/` and user docs with what tests prove; tighten CI and lint; improve discoverability (`sessions list`, worktree merge story, errors); optional lightweight release automation. No new subsystems unless a doc claims they exist and they do not.

**Tech Stack:** Bun workspaces, Biome, `bun test`, Ink TUI, Hono server, `packages/zox-code` bundle (`build.ts` stubs).

## Global Constraints

- Runtime: Bun only (`bun install`, `bun run`, `bun test`).
- `cli` / `sdk` depend on `contracts` + HTTP; no new `core` imports in clients.
- Tests are source of truth when docs disagree on **shipped** behavior.
- Minimize scope: polish ≠ re-open full [Phase 2 plan](./2026-09-17-phase-2-opencode-parity.md) unless listed in Track E.
